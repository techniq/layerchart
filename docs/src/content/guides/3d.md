`@layerchart/3d` draws charts in true 3D with [three.js](https://threejs.org), through [Threlte](https://threlte.xyz). It's a separate package, so charts that don't use it never load three.js. For 3D on the existing `Svg`, `Canvas`, and `Html` layers, see [Isometric](/docs/guides/isometric).

`@layerchart/3d` is released with `layerchart`, at the same version, and installs it. If your project also depends on `layerchart` directly, keep the two on the same version. `three` and `@threlte/core` are peer dependencies, so a project has one copy of each that its own code shares with the charts. Most package managers install them along with `@layerchart/3d`; Yarn needs them listed.

## Quick start

Everything comes from `@layerchart/3d`. `Chart`, `Tooltip`, and `Legend` are LayerChart's own, re-exported, and the marks inside a `Scene` are drawn in 3D.

```svelte
<script>
	import { Axis, Chart, Grid, Points, Scene } from '@layerchart/3d';
</script>

<Chart {data} x="x" y="y" z="z">
	<Scene>
		<Grid />
		<Axis placement="bottom" />
		<Axis placement="left" />
		<Axis placement="back" />
		<Points />
	</Scene>
</Chart>
```

:example{ component="Scene" name="scatter" }

Drag to orbit, scroll to zoom, and right-drag (or shift-drag) to pan.

## How it works

The chart lays out exactly as a flat one would: `x` across the plot's width, `y` down its height, and `z` up off the floor, all through the chart's scales. The `Scene` then stands that plot box up in 3D, with the floor seen at an angle.

- **The `z` scale** measures up from the floor, as it does for [isometric](/docs/guides/isometric#height). Its range defaults to half the floor's shorter side. Set `zRange={({ height }) => [0, height]}` for a cube.
- **Color, series, stacking, and domains** work as on any chart: marks register with the chart, and `fill` / `stroke` take a CSS color, or a data key or function run through the color scale (`c`, `cRange`, ...). CSS variables like `var(--color-primary)` resolve against the page, and follow theme changes.
- **Tooltips** show the row under the pointer, from the nearest mark with `tooltip` set (it's off by default, as for flat marks). Add `tooltipContext` to the chart and a `Tooltip.Root`.

## Marks

| Mark      | Draws                                                                                                              |
| --------- | ------------------------------------------------------------------------------------------------------------------ |
| `Points`  | A sphere per row. `r` sets the radius, else the chart's `r` scale                                                  |
| `Bars`    | A box per row, standing on its `x` × `y` band cell, as tall as its `z` (stacked with `valueAxis="z"`)              |
| `Rect`    | A box per row from pixel `x` / `y` / `width` / `height`, `z` tall (ex. a treemap)                                  |
| `Spline`  | A line through the rows, one per `g` (or `stroke` key, or `c`) value, colored per point                            |
| `Area`    | A curtain from the floor (or `z0`) up to `z` along the rows, one per group                                         |
| `Arc`     | An extruded slice per row (ex. from `d3.pie()`)                                                                    |
| `Polygon` | An extruded polygon per row, from pixel `points`                                                                   |
| `Link`    | A line between two points per row, straight or arched                                                              |
| `Text`    | A label at a point: drawn over the scene, upright and crisp, or with `facing="up"` lying on the surface beneath it |
| `Grid`    | The floor and the two walls behind the plot, with lines at the scales' ticks                                       |
| `Axis`    | Tick labels along an edge: `bottom` for `x`, `left` for `y`, `back` for `z`                                        |

`Grid` and `Axis` keep to the right sides as the camera orbits: the walls stay behind the plot, and the labels on the edges in front. [Surfaces and rasters](/docs/guides/3d-surfaces) and [maps and globes](/docs/guides/3d-maps) have marks of their own.

`z` on a mark takes a data key or function (through the chart's `z` scale), or a number of pixels. Pixel-positioned marks (`Rect`, `Polygon`, `Text`, `Link`) take numbers or functions of the row.

## The view

| Prop       | What it does                                                                              | Default         |
| ---------- | ----------------------------------------------------------------------------------------- | --------------- |
| `rotate`   | Turns the floor about its center, clockwise, in degrees (as `isometric`)                  | `-45`           |
| `tilt`     | Tips it away from the viewer, from `0` (seen from directly above) towards edge on         | `60`            |
| `camera`   | `'perspective'`, or `'orthographic'` to keep sizes true at any depth (as `isometric`)     | `'perspective'` |
| `fov`      | The perspective camera's vertical field of view, in degrees                               | `35`            |
| `margin`   | Room left around the plot box when fitting it into view, as a fraction of its size        | `0.1`           |
| `controls` | Orbit, zoom, and pan with the pointer                                                     | `true`          |
| `drag`     | What a plain drag (and one finger) does: `'rotate'` or `'pan'`; shift-drag does the other | `'rotate'`      |
| `motion`   | Ease to a new `rotate`, `tilt`, or `fov` (ex. `'tween'`)                                  |                 |

The camera fits the whole plot box into the scene, and refits when the chart resizes. A new `rotate` or `tilt` turns the view to it.

```svelte
<Scene camera="orthographic" rotate={-30} tilt={70}>
```

Orbiting updates `rotate` and `tilt`, so binding them keeps controls in step with a drag:

```svelte
<script>
	let rotate = $state(-45);
	let tilt = $state(60);
</script>

<Scene bind:rotate bind:tilt>
```

### Zoom and reset

A scene's `zoomIn()`, `zoomOut()`, and `reset()` (back to the view it started with, fitted and unpanned) are there for buttons of your own, as a flat chart's `transform` has:

```svelte
<script>
	let scene = $state();
</script>

<Scene bind:this={scene}>...</Scene>
<button onclick={() => scene.zoomIn()}>Zoom in</button>
```

The [elevation maps](/docs/guides/3d-maps#elevation) have controls like these.

### Scrolling

Scrolling over a scene zooms it. Set `scrollActivationKey` to only zoom while a key is held, as a flat chart's `transform` does, so scrolling past the chart scrolls the page:

```svelte
<Scene scrollActivationKey="shift">
```

## Lights and shadows

A scene lights itself until it has a `Light` of its own. A `directional` light shines from an `azimuth` (degrees clockwise from the plot's top edge, like a compass bearing on a map) and an `altitude` (degrees above the floor); `shadow` has it cast shadows onto the marks and the floor. An `ambient` light fills in evenly.

```svelte
<Scene>
	<Light azimuth={315} altitude={35} shadow />
	<Light type="ambient" intensity={0.4} />
	...
</Scene>
```

| Prop        | What it does                                                     | Default         |
| ----------- | ---------------------------------------------------------------- | --------------- |
| `type`      | `'directional'` (like the sun) or `'ambient'` (from everywhere)  | `'directional'` |
| `azimuth`   | Which way it shines from, in degrees clockwise from the top edge | `315`           |
| `altitude`  | How high, in degrees above the floor                             | `45`            |
| `intensity` | Brightness, where `1` lights a face turned to it at full color   | `1`             |
| `color`     | A CSS color                                                      | `'white'`       |
| `shadow`    | Cast shadows                                                     | `false`         |

## Limits

- Browsers limit how many WebGL contexts a page can have at once (16 in Chromium). A `Scene` only holds one while it's on screen (or nearly), and gives it back when it's scrolled away.
- Nothing is drawn on the server. The scene renders once it mounts in the browser.
